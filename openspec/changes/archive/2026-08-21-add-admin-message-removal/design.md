## Context

`add-admin-moderation` 的 design.md D1 列了三件「移除訊息不是多一個 `deletedAt`」的理由，
並把它留給後續。這個 change 就是那個後續。

範圍是使用者選定的：**與撤回區分**、**可還原且還原也留稽核**。
停用帳號仍然不在範圍內——它連動 `tokenVersion`、WS 斷線、
「停權期間能不能看歷史」，是另一個主題。

## Decisions

### D1：`removedAt` 與 `retractedAt` 分開，不共用欄位

兩件事對客戶端的語意不同：

| | 使用者撤回 | 管理員移除 |
| --- | --- | --- |
| 誰做的 | 發送者本人 | 平台 |
| 客戶端顯示 | 「訊息已收回」 | 「此訊息因違反規範被移除」 |
| 有時限嗎 | 有（5 分鐘） | 沒有 |
| 可還原嗎 | 不行 | **可以**（誤判） |

共用一個欄位會讓**發送者以為自己撤回了**（他沒有），也讓後台日後想統計
「被移除幾則」時分不出來。而分不出來的代價是：那個統計是判斷平台治理狀況的基本指標。

**兩個標記可以同時存在**：使用者撤回後，管理員仍可移除（例如撤回不夠、
需要留下「這則被平台處理過」的紀錄）。呈現上以移除優先——它是更強的宣告。

### D2：移除是軟刪除，內容保留

與撤回同樣的理由，而且更強：**移除的訊息正是最需要留下證據的那些**。
檢舉調查、申訴、日後的爭議都要看得到原文。

內容仍然只從後台的檢舉詳情路徑讀得到（`add-admin-moderation` 建立的那條），
前台的任何路徑都不回傳它。遮蔽依然只寫在 `toMessage()` 一處。

### D3：可還原，而且還原也留稽核

誤判在審閱情境是真實的。「不能還原」會讓管理員傾向不敢處理——
**一個不敢用的工具等於沒有工具**。

但還原本身也是權力的行使，因此同樣寫稽核。更重要的是：
**反覆移除再還原本身就是可疑行為**，而只有兩邊都記才看得出那個模式。

還原只清除 `removedAt` / `removedBy`，**不碰 `retractedAt`**——
如果使用者原本就撤回過，還原之後它應該回到「已收回」而不是完全正常。

### D4：移除的訊息仍出現在歷史與補齊中

與撤回完全相同的理由，這裡不重複論證：濾掉會讓 `seq` 出現洞，
而補齊的客戶端無法區分「被移除」與「我漏收了」。

`content` 為空字串、`removedAt` 有值。客戶端據此顯示「因違反規範被移除」。

### D5：移除與還原是獨立端點，不是檢舉的附屬動作

`DELETE /api/admin/moderation/messages/:messageId` 與
`POST /api/admin/moderation/messages/:messageId/restore`。

**不做成「判定檢舉時順便移除」**：那會把兩個決定綁在一起，
而它們的正確組合有四種（判定成立但不移除、移除但檢舉駁回…）。
綁在一起會逼管理員在不想要的時候做出另一個決定。

也不需要「這則訊息有沒有被檢舉過」才能移除——管理員可能從別的管道
（使用者私訊、主動巡邏）發現違規內容。**移除的授權來自 RBAC，不來自檢舉的存在。**

### D6：推播用兩個獨立事件，不共用一個帶 `action` 的事件

`server:messageRemoved` 與 `server:messageRestored`。

共用一個事件（例如 `messageModerated` 帶 `action: 'REMOVED' | 'RESTORED'`）
會讓客戶端在每個 handler 裡先分支。兩個事件的 payload 也確實不同：
移除要帶 `removedAt`，還原要帶「還原後的狀態」（可能仍是已撤回）。

## Open Questions

- **要不要通知發送者**：目前只推播給房間成員（發送者若在房間內也會收到，
  但不是專門的通知）。「你的訊息被移除了」是產品決定——
  它牽涉到申訴管道，而那還不存在。
- **移除的原因要不要記錄**：目前沒有 `removeReason`。檢舉的 `reviewNote` 已經
  可以承載理由，而移除與檢舉刻意解耦（D5）——兩者要怎麼關聯等有實際使用再說。
- **統計指標**：「本週移除幾則」這類指標等 M4 後台介面有實際需求再加。

## 為停權預留了什麼

什麼都沒預留，這是刻意的。

停權需要的是**帳號層級**的狀態與 `tokenVersion` 的連動，與訊息層級的移除沒有共用結構。
現在加任何欄位都是替一個還沒設計的東西猜規格。

真正留下的是這份 design 的 D1——**下一個做停權的人會先讀到
「兩件事對使用者的語意不同時，不要共用欄位」**，那個教訓在停權上同樣適用
（「自己登出」與「被停權」不該長得一樣）。
