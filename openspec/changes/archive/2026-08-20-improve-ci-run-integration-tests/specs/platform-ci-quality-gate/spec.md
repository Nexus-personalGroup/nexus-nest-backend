## ADDED Requirements

### Requirement: 跨實例的保證必須在 CI 驗證

CI SHALL 執行驗證「多個實例之間」行為的測試，並提供其所需的真實外部服務。
MUST NOT 以 mock 取代跨實例路徑所依賴的服務。

既有的 e2e 需求涵蓋的是「單一實例內的 API 行為對真實資料庫」，
**涵蓋不到「多個實例之間」這個維度**——後者的失效方式在單一實例內完全看不出來。
只在單一實例驗證時，拿掉跨實例廣播機制的改動會一路綠燈通過。

驗證跨實例行為的測試所需的外部服務連線設定 MUST 由該測試自身的環境設定明示，
MUST NOT 依賴其他來源的預設值恰好一致。兩個獨立決定湊巧對上時，
改動任一方都會讓測試以「連不到服務」的形式失敗，而症狀指不到原因。

#### Scenario: 移除跨實例廣播機制

- **WHEN** 有人拿掉 Socket.IO 的 Redis adapter，或改壞它的掛載時機
- **THEN** CI 失敗——單一實例內的行為不受影響，因此只有跨實例測試會發現

#### Scenario: 以 mock 取代跨實例所依賴的服務

- **WHEN** 跨實例測試改用 mock 的 Redis
- **THEN** 違反本需求——pub/sub 正是被驗證的機制本身

#### Scenario: 外部服務連線靠預設值巧合

- **WHEN** 測試未宣告所需服務的連線設定，僅依賴框架或其他設定檔的預設值
- **THEN** 違反本需求
